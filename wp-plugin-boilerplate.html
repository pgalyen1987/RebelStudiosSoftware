What you are actually buying

Not a framework you have to learn, and not a starter theme with your problem left as an exercise. It is the part of a freemium plugin that is identical every time, already built and already shipped: the scaffolder that stamps out a new plugin, the settings and admin layer, the licence gate, and the tooling that turns the result into a zip you can submit.

The scaffolder takes a name, a function prefix and a slug, and produces a plugin that activates cleanly on a fresh WordPress install before you have written a line of your own code. Constants, namespacing, text domain, settings screen and gate are wired at that point — you add your feature to a working plugin rather than assembling one.

How the licence gate is built — and why that shape

WordPress.org does not permit a plugin hosted in its directory to lock its own features behind a payment, so the architecture is not a preference; it is the rule. The boilerplate follows the compliant pattern: a genuinely complete free plugin in the directory, and a separate Pro add-on distributed by you that unlocks the paid surface.

Gating a feature is a single call, and the important property is what happens when the answer is no. The gate degrades to the free behaviour rather than erroring, disabling the screen, or destroying data the user has already created. That is the failure mode that generates refunds and one-star reviews, and it is designed out rather than left to whoever writes the feature.

The same discipline applies when your licence server is unreachable. A check that fails closed will disable a paying customer’s site during your outage, so verification is built to fail open within a grace window — the customer keeps working, and the check retries later.

What it does not include

Being clear about this is more useful than a longer feature list:

  • No licence server. The plugin side of verification is here; the service that issues and validates keys is yours to run or to buy. The gate is written against a simple contract, so pointing it at an existing service is configuration rather than surgery.
  • No payment processing. Sell through Gumroad, Lemon Squeezy, WooCommerce or anything else.
  • No feature. The idea is still your job. This is the eighty percent that is the same for every plugin, not the twenty percent that makes yours worth buying.

Who this is for

It is for a developer who has decided to ship a commercial plugin and does not want to spend the first fortnight rebuilding a settings page and a licence check for the third time. If you are shipping one plugin, it saves you that fortnight. If you are shipping several, it is the difference between each one starting from zero and each one starting from a known-good base.

It is not for you if you want a page builder, a plugin generator that writes your feature, or a hosted platform. And if you have already built and shipped a freemium plugin you were happy with, you have essentially built this — there is nothing here you could not write yourself, which is precisely why it is priced where it is rather than sold as a subscription.
